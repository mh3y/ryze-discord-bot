**Production-safety posture during this audit:** nothing was modified, pushed, deployed, or written to any database. The legacy stack was assessed from source only.

## 3. Architecture reality

Three facts drive most findings:

1. **Two data stores, split brain.** The bot has its **own Postgres** (`ryze_bot`, SQLAlchemy) *and* pushes to **Supabase via the Node CRM** (`ryze-portal-api` on Render). The live calendar sync (`sync_all_calendars_portal`) writes **only to Supabase**. Several loops still **read the local Postgres**, which is **empty in production** (the code's own comments say so). → dead features (§4, DEF-2/3).
2. **A legacy FastAPI portal (`bot/api/`) still defined in `docker-compose.yml`.** `docker-compose.yml` describes a 5-service VPS stack (db, migrate, **api**=this FastAPI, bot, **web**=nginx+React on 80/443). But CI (`deploy.yml`) **only redeploys the `bot` container**. Production moved the frontend to Vercel and the API to Render. So `api`/`web`/`db` are almost certainly **stale but possibly still running** with `restart: unless-stopped`. → conditional security surface (§4, DEF-4/5/6).
3. **The repo is 7 weeks behind the CRM.** All the recent CRM hardening has no counterpart here.

## 4. Defect register (severity-ranked, deduped)

Severity: **P0** = critical/urgent · **P1** = major (breaks a core feature or real security hole) · **P2** = moderate · **P3** = minor.
"CONDITIONAL" = only exploitable if the legacy FastAPI/`web` stack is actually deployed on the VPS.

### P0 — Critical

**DEF-1 · Real Discord OAuth client secret committed to a PUBLIC repo** — `/.env.production.example:43` (tracked since `9c3b3f7`)
Confirmed first-hand: `DISCORD_CLIENT_SECRET=WgbM…` is a real secret (client ID + guild ID also real; other secrets on the file are placeholders). Anyone can read it. Enables impersonation of the "Login with Discord" OAuth app.
**Fix (owner):** rotate the Discord client secret in the Developer Portal **now**; replace the value with a placeholder; scrub from history (BFG/filter-repo); keep example files placeholder-only. *This is an owner action — I cannot rotate it.*

**DEF-2 · Lesson reminders, auto-threads, and homework are inert in production** — `reminders.py:55`, `lesson_threads.py:47`, `homework.py:140` read local `Lesson`; live sync `lesson_service.sync_all_calendars_portal` writes only Supabase (its docstring at `lesson_service.py:217-219` says the local table "is empty in production").
Result: in prod the local `Lesson` table is empty → **no reminder DMs, no channel reminders, no auto-created lesson threads ever fire**, and `/set_homework` fails "Lesson not found" for every real lesson. Corroborated by the data-store split in §3.
**Fix:** point the reminder/thread/homework read paths at the same source of truth the sync writes (fetch from the portal API), or have the portal sync also upsert the local `Lesson`/`ClassGroup` tables.
*Conditional caveat: if something out-of-band populates local `Lesson` in prod this de-escalates — but no code path does so. **Verify by checking `ryze_bot.lessons` row count on the VPS.***

**DEF-3 · Lesson-cancellation notifications are dead code** — `calendar_sync.py:59,96`; `lesson_service.py:226,259`
`sync_all_calendars_portal` initialises `newly_cancelled: []` and never appends; `_handle_cancellations` always early-returns. A tutor cancelling a lesson in Google Calendar produces **no DM, no channel alert, no thread notice** to students/tutors.
**Fix:** detect cancelled-transitions in the portal sync and return real `(lesson, class_group)` tuples, or drive notifications off the sync response.

**DEF-4 · FastAPI JWT forgery via public default secret** *(CONDITIONAL)* — `bot/api/auth.py:42,74,78`
`JWT_SECRET_KEY` defaults to `"CHANGE_ME_USE_A_REAL_SECRET"` read directly from `os.getenv`. If the legacy API is live and the env var is unset, anyone can forge `{"sub":"user:<admin>","role":"admin"}` → full admin over `/api/admin/*`. No `iat/jti`, non-revocable.
**Fix:** fail closed if secret missing/sentinel; import the single `config.JWT_SECRET_KEY`. **But first: confirm the FastAPI is even running.**

**DEF-5 · `DASHBOARD_API_KEY` baked into the public frontend bundle** *(CONDITIONAL)* — `docker-compose.yml:90` (`VITE_PORTAL_API_KEY: ${DASHBOARD_API_KEY}`)
Vite inlines `VITE_*` into shipped JS. That key is both the bot's Bearer token to the CRM **and** the FastAPI static-admin key (`auth.py:166` → synthetic admin). If the `web` container is/was served from this compose file, "View Source" leaks an admin-equivalent key.
**Fix:** never ship a server secret to the browser; give the bot its own dedicated secret; rotate `DASHBOARD_API_KEY`. Confirm Vercel has no `VITE_PORTAL_API_KEY`.

### P1 — Major

**DEF-6 · Legacy `api`/`web`/`db` likely still running, unpatched, on the VPS** *(CONDITIONAL)* — `docker-compose.yml` vs `deploy.yml`
`web` binds 80/443; `restart: unless-stopped`. A stale FastAPI (synthetic-admin path) + nginx serving an old bundle + a Postgres holding a **second copy of student data**, none patched by CI. **See §8 for the verify/decommission runbook.**

**DEF-7 · `/delete_user` fails with FK violation for any real user** — `admin.py:748-793`; no cascade on `attendance_records`/`voice_sessions` (`attendance.py:45-47,101-103`; `user.py:41-46`)
Deletion removes only memberships + user; attendance/voice rows have no `ondelete` → Postgres raises `ForeignKeyViolation`, the session rolls back, and the "🗑️ User Deleted" reply never sends. Works only for zero-history users. The confirmation dialog implies success that never happens.
**Fix:** soft-delete (`active=False`, matching the codebase pattern) **or** add cascades + delete children first + report failure to the admin.

**DEF-8 · Attendance mis-marks fully-present students as `left_early`** — `attendance.py:418-436` + `attendance_service.py:173-207,159-168` (found independently by TWO agents → high confidence)
`total_minutes` accrues only in `close_voice_session`. The finalise loop fires the instant `end_time <= now` while students are still in the channel (`left_at=None`, `total_minutes=0`) → `calculate_attendance_status` returns `left_early`/`absent` for present students. Also affects any bot restart mid-lesson.
**Fix:** in `finalise_lesson_attendance`, close all open `VoiceSession`s at `min(now, lesson.end_time)` and fold into `total_minutes` **before** computing status.

**DEF-9 · Class auto-provisioning + self-heal broken by an over-broad regex** — `class_discovery.py:51,116,209`
The "skip primary account calendar" guard uses `^…@…\.…$`, which matches **every** `…@group.calendar.google.com` class calendar too (verified empirically). `_should_skip` runs before provisioning → new classes are never auto-created and Discord-ID self-heal never runs. (Existing classes still get lessons, since the portal sync path doesn't call `_should_skip` — hence P1 not P0.)
**Fix:** use the `primary` flag from `list_calendars` (`google_calendar_service.py:77`), not an email-shape regex.

**DEF-10 · Synchronous Google API calls block the asyncio event loop** — `google_calendar_service.py:33,34,70,103` called from async services
`creds.refresh()` / `service…execute()` are blocking HTTP run directly on the loop every sync (default 10 min). Blocks the Discord heartbeat (gateway can drop), delays the voice-state events attendance depends on, and hangs slash commands. A DB connection is also held open across the blocking calls.
**Fix:** `await asyncio.to_thread(...)` the Google calls; fetch before opening the DB session.

**DEF-11 · FastAPI tutor role is unscoped — broad horizontal IDOR** *(CONDITIONAL)* — `bot/api/routes/admin.py` (attendance PATCH :754; progress-reports POST :1216; homework :2249-2478; lessons/resources reads)
No notion of "which classes a tutor teaches." A single tutor JWT can read/write attendance, homework, submissions, and progress reports for **any** student in **any** class, and can attribute a report to another tutor and publish it to a parent.
**Fix:** add a tutor→class ownership check on every `require_admin_or_tutor` `{id}` route/list; ignore client-supplied `tutor_user_id`.

**DEF-12 · FastAPI parent portal + student-link creation 500 on real data** *(CONDITIONAL)* — `bot/models/portal_auth.py:122`, `parent.py:232`, `admin.py:331`
Model maps attribute `relationship_type` → column `"relationship"`, but code uses `.relationship`/`relationship=` → `TypeError`/`AttributeError`. `POST /parents/{id}/link-student` and `GET /parent/portal` (for any parent with a child) always 500. (Strong secondary evidence the FastAPI isn't the live portal.)
**Fix:** use `relationship_type` consistently.

**DEF-13 · `deploy/deploy.sh` targets a non-existent branch + resurrects the legacy stack** — `deploy/deploy.sh:22-23` (`git pull origin main`; repo branch is `master`); runs the full 5-service `docker compose up`.
A manual `./deploy.sh` either fails at `pull origin main` or, if it proceeds, rebuilds/restarts the stale api/web/db and runs Alembic against `ryze_bot` — reviving the decommissioned stack and contradicting CI.
**Fix:** fix the branch; reduce to the bot-only flow or delete; archive the legacy compose services.

**DEF-14 · CI deploy: destructive reset, no health gate, no rollback** — `.github/workflows/deploy.yml:44-61`
`git reset --hard FETCH_HEAD` wipes on-box changes; `.env` is clobbered from secrets each run; after `up -d` there's only `sleep 3` + tail — a bot that boots then crash-loops reports the job **green** with no alert/rollback.
**Fix:** post-start health gate (poll ready / inspect restart-count), keep previous image tag for rollback.

### P2 — Moderate

**DEF-15 · `discord_permission_sync` grants access to ANY channel for ANY member, unvalidated** — `bot_jobs.py:114-182`
Grant path applies `view+send` straight from the CRM payload with no check that the channel belongs to a class or that grantees are enrolled. A compromised CRM / leaked key / buggy producer can grant a student access to a private staff channel. (Revoke path has admin/owner guards; grant path has none.)
**Fix:** validate `channel_id` against known class channels and grantees against active `ClassGroupMember` rows before applying overwrites.

**DEF-16 · Portal role classification is name-based; parents mis-synced, cosmetic "Admin" role → CRM admin** — `members.py:124-136`
Classifies by Discord role **name**; only admin/tutor/student (parents always become `student`); a role literally named "admin" escalates to CRM admin. Periodic re-sync can overwrite a correctly-linked role.
**Fix:** classify by role **ID** or real `administrator` permission; add parent detection; make periodic push non-destructive.

**DEF-17 · `_sync_all_members` local role update is a dead no-op** — `members.py:194-199` (a discarded `select`) → local `users.role` never updates after creation; diverges from Discord/CRM permanently. **Fix:** use `update(...)` or drop the dead code.

**DEF-18 · `bot_jobs` poll loop can die permanently on a malformed job** — `bot_jobs.py:82-93` — `job["id"]` is outside the try; a job missing `id` raises `KeyError` that escapes the `tasks.loop` → all job processing halts until restart. **Fix:** move id/logging inside try; add `@_poll_loop.error` restart handler.

**DEF-19 · Fire windows have no catch-up — one slow tick permanently drops a reminder/thread** — `reminders.py:66`, `lesson_threads.py:56` — 1-min equality window on a `tasks.loop(minutes=1)` that drifts; a 65s gap skips forever despite being online and despite dedup making catch-up safe. **Fix:** gate on `fire_at <= now AND not has_reminder_been_sent(...)`.

**DEF-20 · Homework reminders re-spam on every bot restart** — `homework.py:31` — dedup is an in-memory `set` reset on restart; any redeploy in the 25h window re-DMs every student. **Fix:** persist dedup (small table or reuse `reminder_log`).

**DEF-21 · Tutor manual attendance mark writes wrong column + gets clobbered** — `attendance_service.py:225-229` writes `record.status` (system column) not `tutor_marked_status`/`tutor_marked_at`; `finalise` then overwrites it. Destroys the system-vs-tutor distinction and can silently revert a tutor's decision. **Fix:** write `tutor_marked_status`+`tutor_marked_at`; never let finalise touch it.

**DEF-22 · No unique constraint on `attendance_records(lesson_id,user_id)`** — model+migration lack it; `get_or_create` SELECT-then-INSERT can duplicate under concurrent voice events, splitting `total_minutes` and risking `MultipleResultsFound`. **Fix:** add `UniqueConstraint` + migration (or `ON CONFLICT`).

**DEF-23 · Static `DASHBOARD_API_KEY` = synthetic admin, unaudited** *(CONDITIONAL)* — `bot/api/auth.py:166` — one static key → full admin write on the FastAPI, with audit skipped (`user_id is None`). **Fix:** separate bot S2S key from portal admin auth; never synthesize admin from a static key.

**DEF-24 · N+1 in `get_missing_homework`** — `homework_service.py:103-116` — T×S sequential queries. **Fix:** one `IN` query + dict lookup.

**DEF-25 · Dockerfile runs as root, no pinning, no `.dockerignore`** — `/Dockerfile` — root user, `>=` version ranges (non-reproducible), gcc shipped in final image, `COPY . .` pulls `.git`/tests/`.env`. **Fix:** non-root `USER`, multi-stage, pin/lock, add `.dockerignore`.

**DEF-26 · Secret env var named differently across repos** — bot sends `DASHBOARD_API_KEY`; CRM reads `BOT_API_SECRET`. Values must be byte-identical across two deploy environments; independent rotation → silent 401s and all sync stalls (errors swallowed, no alert). **Fix:** document the required equality; add a bot startup auth self-check that logs loudly on 401.

**DEF-27 · `config.py` prod-critical URLs fall back to localhost** — `PORTAL_BASE_URL`, `DISCORD_REDIRECT_URI` default to `http://localhost:5173`; unset in prod → parent-invite links point to localhost / OAuth breaks. **Fix:** require them (or validate non-localhost when a prod flag is set).

### P3 — Minor (verify/optional)

- **DEF-28** · Dead CRM route `POST /api/bot/attendance` (`bot.ts:633`) — no bot caller; writes canonical `Attendance` that `sync-voice-sessions` doesn't → drift risk. Mark deprecated or remove.
- **DEF-29** · Job complete/fail callbacks are fire-and-forget (`bot_jobs.py:49-62`) — a lost `/complete` leaves the job stuck in `processing` (not re-pollable) after the side-effect ran. (CRM Wave-D reaper now marks these `failed` — partial mitigation.)
- **DEF-30** · `ALTER TYPE … ADD VALUE` inside a migration txn (`a1b2c3d4e5f6:28`) — breaks on PG<12; fragile on PG12+. Move to its own migration.
- **DEF-31** · `portal_api` parses JSON before checking `resp.ok` + no retry (`portal_api.py:61-86`) — Render cold-start HTML 502/503 → opaque `JSONDecodeError`; 30s timeout < ~50s cold start. Read text, check ok first, add bounded retry.
- **DEF-32** · DST-transition-day off-by-one in `get_todays_lessons` (`lesson_service.py:104`) — `.replace(hour=0)` carries stale offset. Use fresh `SYDNEY_TZ.localize(...)`.
- **DEF-33** · `minutes_until`/`lesson_duration_minutes` crash on naive datetimes (`time_utils.py:47-54`). Normalise tz first.
- **DEF-34** · FastAPI parent-account enumeration + no rate limit (`auth.py:153`); money as `float` (`admin.py:814`); unbounded alert-generate N+1 (`admin.py:1468`) — all CONDITIONAL on legacy API.
- **DEF-35** · `get_refresh_token.py` hardcodes a personal `C:\Users\micha\Downloads\…client_secret…json` path + `OAUTHLIB_INSECURE_TRANSPORT=1`; ships in image. Parameterise + `.dockerignore`.
- **DEF-36** · Latent async lazy-load (`discord_service.py:25` `class_group.tutor`) can `DetachedInstanceError`; no `pool_recycle` on engine; `link_class_role` back-fills tutor as student; logging has no redaction filter (nothing sensitive logged today). Minor hardening.
